THE WARM ICING MODEL - map from every reported result to the code and data behind it
====================================================================================
Bayesian calibration of a package-substrate material map from measured thermal warpage.
The posterior is exactly an Ising model; it is sampled with quantum-enhanced MCMC
(Layden et al., Nature 619, 282 (2023)) and the proposal circuit is benchmarked on
IonQ, IBM and Rigetti hardware. "WarpCal-Ising" is the internal name of the benchmark
and appears in file names and data.

Quick check:  pip install -r requirements-local.txt  then  python verify_all.py
  Recomputes every hardware number from the raw counts files and prints the benchmark
  numbers from the saved outputs, each next to the value quoted. Add --specs to rebuild
  the 12-qubit circuit specs from main.py.

Credentials (only for re-running on hardware): set QISKIT_IBM_TOKEN, QISKIT_IBM_INSTANCE, IONQ_API_KEY
or DWAVE_API_TOKEN in your environment or in a .env file next to the script. Never commit keys.


FOLDERS
-------
qollab/                    Project page for Qollab (HTML, CSS, JavaScript): runs the 9- or 12-qubit circuit on
                           the backend chosen in the Run dialog, scores every run, documentation and credits.
main.py                    End-to-end demo (calibration + one quantum proposal step) as a
                           single script. Runs on any Qiskit backend; the runner
                           provides the global `backend`. Local run:
                             python -c "import main; from qiskit_aer import AerSimulator;
                                        main.backend = AerSimulator(); main.main()"
benchmark/                 Physics models, benchmark data, calibration and sampler analysis
hardware_9q/               9-qubit proposal-circuit tests and all 9-qubit hardware counts
hardware_12q/              12-qubit circuit (the one in main.py), depth ladder, annealing baseline

R16 Detailed balance of the quantum proposal (hardware_12q/check_detailed_balance.py)
  The noiseless 3-step Trotter circuit gives an exactly symmetric proposal: max |Q(x->y) - Q(y->x)|
  = 7e-16, so plain Metropolis converges to the exact posterior (stationary TVD 0.0000). Reason:
  reversing the gate order equals conjugating by a diagonal phase, which leaves |amplitudes| unchanged.
  The benchmark's exact-evolution proposals are symmetric too, and its noise model (mixing with a
  uniform proposal) keeps them symmetric. Real hardware noise need not be symmetric: an example 3%
  1->0 readout bias per bit gives a stationary TVD of 0.011 under plain Metropolis. Running the full
  sampler on hardware would need symmetrisation (for example random bit-flip twirling) or a
  Metropolis-Hastings correction with an estimated proposal ratio. Not yet done.

5. WHAT THESE RESULTS DO NOT SHOW
---------------------------------
- No wall-clock advantage: at 9-12 regions every posterior is enumerated exactly on a laptop.
- Speed-ups in R5/R6 are modelled (exact gaps with a depolarizing-style proposal model), not
  measured by running the full sampler on hardware.
- Benchmark boards are synthetic (3D FEA); only the forward physics is checked against real
  measurements (R2).
- The full sampler was not run on hardware; asymmetric hardware noise would bias plain Metropolis (R16).
- Hardware runs are few (1-3 per device) and vary from run to run; no runs are pooled.
